\begin{abstract}
Zero-knowledge machine learning (zkML) enables clients to verify outsourced inference, but generating proofs is slow and memory intensive. Partitioning a model into smaller computations can reduce proving costs and enable parallel execution. When multiple requests share a prover cluster, however, their proof tasks compete for compute and memory.

We present \emph{zkInfer}, a distributed runtime that coordinates proof generation across concurrent inference requests. Our characterization shows that proof tasks vary substantially in duration and memory use, and that their memory requirements change during execution. Reserving enough memory for a task's most demanding stage throughout its execution can therefore unnecessarily delay other tasks. zkInfer distributes tasks across prover nodes and uses measurements from previous executions to decide when each stage can proceed within the available memory. It also reuses compiled circuits and proving keys across requests, avoiding repeated setup work without changing the proving protocol.

Under a 48~GiB proving memory budget, zkInfer reduces median MobileNetV2 request latency by up to 8.8\% compared with reserving memory for each task's most demanding stage until completion. Across three workloads, increasing the prover pool from one to ten nodes yields \(10.5\)--\(12.7\times\) speedups for individual requests.
\end{abstract}
