\begin{abstract}
Zero-knowledge machine learning (zkML) enables clients to verify outsourced inference, but generating proofs is computationally expensive and requires substantial memory. Partitioning a model into smaller computations can reduce these costs and allow their proofs to be generated in parallel. Serving multiple inference requests, however, requires coordinating this work across machines with limited resources.

We characterize partitioned zkML workloads and show that proof-generation tasks differ substantially in execution time and memory requirements. Memory use also varies during each task, while compiled circuits and proving keys can be reused across requests. These observations motivate \emph{zkInfer}, a distributed runtime for zkML proof serving. A coordinator distributes tasks from concurrent requests across prover nodes. Each node uses measurements from previous executions to determine which tasks can proceed within its memory budget. By accounting for how memory requirements change during execution, zkInfer allows tasks to overlap without reserving each task's maximum estimated memory requirement throughout its execution. It also reuses compiled circuits and proving keys without modifying the proving protocol.

With a 48~GiB memory budget for proving, zkInfer reduces median MobileNetV2 request latency by 4.2--8.8\% across bursts of 2--16 requests compared with reserving each task's maximum estimated memory requirement until completion. Increasing the prover pool from one to ten nodes yields \(10.5\)--\(12.7\times\) speedups for individual requests across TinyBERT, MobileNetV2, and NanoGPT. Reusing setup artifacts reduces repeated setup time by 96.3--98.6\%. The results demonstrate the benefits of distributed proof generation and setup reuse, with further latency reductions from accounting for changing memory requirements when memory limits concurrent execution.
\end{abstract}
